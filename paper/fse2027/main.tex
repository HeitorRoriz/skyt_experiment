%% ---------- ABSTRACT ----------
\begin{abstract}
Existing code-generation benchmarks score a sample against a behavioral oracle.
They do not measure how much the \emph{structure} of passing code varies when
the same prompt is regenerated.
We propose a \textbf{structural repeatability protocol}: $N$ independent
generations, a 14-property structural distance, and population reports based on
pairwise U-statistics and certified modal mass.
The protocol separates \emph{measurement} (how scattered are the outputs?) from
\emph{policy} (which verified form should count as the canon?).
On contracted Python tasks, behavioral pass rates are high ($\approx$98\%) while
end-to-end pairwise exact-match is 61.0\% (MSR, 15 tasks, 4{,}500 generations)
and 67.5\% (SBES, 12 contracts, 3{,}600 generations).
Repairing toward the first certified generation and toward a certified consensus
form are different policies; we report both and do not mix them.
On a 30-task HumanEval+ run (1{,}200 generations, no style contracts), plus-test
pass is 80.5\%, end-to-end pairwise exact-match is 56.9\%, and match to the
shipped human solution is 9.3\%.
A post-generation canonicalizer (\skyt{}) applied to those same 1{,}200 programs
raises end-to-end pairwise exact-match to 75.9\% (0 regressions, 34 rescues);
most rewrites substitute the named function with the stored consensus program.
\end{abstract}

\keywords{LLM code generation, structural repeatability, U-statistics, canonicalization, HumanEval+, software measurement}

\section{Introduction}
\label{sec:intro}

Correctness benchmarks for LLM code generation---HumanEval~\cite{chen2021evaluating},
MBPP~\cite{austin2021program}, SWE-bench~\cite{jimenez2024swebench}---ask whether
\emph{a} generated artifact passes tests.
Production pipelines regenerate: CI re-runs generators, agents retry, and
independent developers issue the same prompt.
Behavioral oracles cannot tell two passing regenerations apart, yet the
artifacts can differ in structure~\cite{ouyang2023llm}.

This paper's primary contribution is a \textbf{benchmark overlay} that measures
that structural scatter (\textbf{C1}).
We then show that the choice of reference form (the \emph{canon}) is a policy,
not a measurement, and compare first-compliant anchoring to a Certified
Consensus Canon (\textbf{C2}).
We apply the protocol to author-written contracted tasks (\textbf{C3},
Results~A) and to HumanEval+~\cite{liu2023evalplus} (\textbf{C3}, Results~B).
Finally we rescore a post-generation repair tool, \skyt{}, under the same
metrics (\textbf{C4}).

The protocol does \emph{not} select the best program and does \emph{not} aim at
a shipped human solution.
It selects the most reproduced verified form, then measures whether other
generations match it.
``Same form'' means identical structure under a 14-property distance of 0
(numeric tolerance $10^{-12}$).

\paragraph{Not in this paper.}
Generation-by-construction (``Code DNA'') is a separate vision paper.
We do not claim MISRA~C~\cite{misra2012} or NASA Power-of-10~\cite{holzmann2006power}
compliance for any contract.
We do not score \skyt{} by pass@$k$ or by match to the HumanEval canonical
solution.

\section{Motivation}
\label{sec:motivation}

Regeneration is routine.
If two passing programs differ in structure, a reviewer, a later model call, or
a CI retry must re-read code that the test suite treats as interchangeable.
On the contracted tasks, among pairs of generations that both pass, mean
line-level churn is 13.1\% (MSR) and 13.8\% (SBES), about 2.7 changed lines on
$\approx$12-line functions, and tracks temperature (3.2\% at $T{=}0.0$ to
23.1\% at $T{=}1.0$).

A natural operational response is to freeze the first program that passes.
That is a \emph{policy}.
On the contracted tasks, the first certified generation matches the certified
consensus form in only 40.5\% of MSR configs that have a consensus (40.6\%
SBES).
Commercial APIs are not bit-deterministic at $T{=}0$~\cite{ouyang2023llm}.
Freezing one output works until anyone re-runs the prompt.

Style contracts can pin some axes (we observe zero recursion-schema flips among
passers on the contracted tasks because those contracts constrain style).
The behavioral--structural gap still remains.
That is the measurement problem this protocol is for.

\section{Related Work}
\label{sec:related}

\paragraph{Correctness benchmarks.}
HumanEval~\cite{chen2021evaluating}, MBPP~\cite{austin2021program}, and
SWE-bench~\cite{jimenez2024swebench} score pass@$k$ against tests.
HumanEval+~\cite{liu2023evalplus} keeps the same 164 prompts and replaces the
hidden tests with a larger extra suite.
These protocols do not report structural dispersion across $N$ passing samples.

\paragraph{LLM variability.}
Ouyang \etal{}~\cite{ouyang2023llm} document non-determinism in code
generation; temperature changes output diversity~\cite{zhu2024hot}.
Studies of developer interaction~\cite{vaithilingam2022expectation,barke2023grounded}
treat a generation as a single artifact.
We measure scatter of structure given tests (and, when present, contracts).

\paragraph{Equivalence and clones.}
Distance 0 on our extractors is closer to clone/equivalence measurement than to
pass@$k$~\cite{roy2009clone}.
We do not claim observational equivalence or algorithm identity
(Section~\ref{sec:threats}).

\paragraph{Repair and contracts.}
Program repair and constrained decoding are adjacent.
\skyt{} is a post-generation canonicalizer, not a generator~\cite{roriz2026skytmsr}.
On HumanEval+ in this draft it is consensus pick plus AST repair plus rollback,
with no style contract.

\section{The Structural Repeatability Protocol}
\label{sec:protocol}

\subsection{Inputs and regenerations}
A \emph{task} supplies a prompt, a behavioral oracle (unit tests), and optional
static constraints (a \emph{contract}).
An experimental \emph{config} is one task $\times$ one model $\times$ one
temperature.
For each config we draw $N$ independent generations
($N{=}20$ on contracted tasks; $N{=}10$ on the HumanEval+ run in this draft).

\subsection{Certification}
\label{sec:certification}
\emph{Certified} is a predicate on a generation, and it is not the same on both
datasets.
On contracted tasks, certified means the behavioral oracle passes \emph{and}
the contract checker passes.
On HumanEval+, certified means the HumanEval+ extra tests (plus) pass.
Original HumanEval (base) tests are stored and are never mixed into
certification.
If a generation cannot be represented by the structural extractors, it is
structurally invalid; certified generations must also be valid.

\subsection{Structural sameness}
\label{sec:sameness}
We extract a vector of 14 properties from each generation
(control-flow signature, data-dependency graph, execution paths, function
contracts, complexity class, side-effect profile, termination properties,
algebraic structure, numerical behavior, logical equivalence, normalized AST
structure, operator precedence, statement ordering, recursion schema).
A previously used behavioral-signature extractor is disabled because it
executed generated code.
Two generations are the \emph{same form} when the distance on this vector is 0
(tolerance $10^{-12}$).
Headline exact-match rates are weight-independent: distance 0 requires all
extracted properties to match.
Mean distances are descriptive only.
Where a contract allows flexible naming, comparison includes $\alpha$-renaming
under that policy.

Distance 0 means these extractors agree.
It is not semantic equivalence of all programs
(Section~\ref{sec:threats}).

\subsection{Population measures (not policies)}
\label{sec:measures}
Let a config have $N$ generations.
Write $C(N,2)$ for the unordered pairs.
A pair \emph{end-to-end matches} if both generations are certified and their
distance is 0.
Pairs in which either generation fails contribute 0.

\begin{enumerate}
  \item \textbf{End-to-end pairwise exact-match} (primary pairwise report;
        MEASURE~1):
        \[
          R_{\mathrm{e2e}}
          \;=\;
          \frac{\#\{\{i,j\}\,:\,\text{both certified and distance }0\}}{C(N,2)}.
        \]
        This is a U-statistic.
        Failures remain in the denominator.
        It is defined on every config.
  \item \textbf{Certified pairwise exact-match} (secondary):
        the same identity check restricted to pairs of certified generations.
        Undefined when fewer than two generations certify; those configs are
        omitted from the mean of this column and the omission is reported.
  \item \textbf{Certified modal mass:} size of the largest certified
        distance-0 class, divided by $N$ (failures count).
  \item \textbf{Pairwise distance} (secondary): mean distance among
        structurally valid pairs.
\end{enumerate}

Pairs within a config share generations and are not independent Bernoulli
trials.
Inference aggregates \emph{one score per task} (or contract) and uses a
cluster bootstrap (10{,}000 resamples, seed 20260723).
We do not treat $C(N,2)$ pairs as binomial trials and do not put a Wilson
interval on in-sample modal share.
A Wilson interval is valid only for a frozen canon scored on an independent
batch; this draft does not report such an interval as a headline.

\subsection{Canon policy (separate from measurement)}
\label{sec:canon-policy}
Measurement asks how scattered the outputs are.
A \emph{canon} is a chosen reference form used as a repair target or as a
held-out predictor.
That choice is a policy.

\textbf{Certified Consensus.}
Among certified, structurally valid generations, form distance-0 equivalence
classes (transitivity checked).
Take the largest class (mode).
If several classes share that size, take their members as candidates.
Among candidates, pick the medoid relative to \emph{all other certified}
samples (smallest mean distance), then the lexicographically smallest source
string, then index.
The result is an observed generation.
If nothing certifies, there is no canon; repair is skipped.

\textbf{First-compliant (first-valid).}
Repair toward the first generation in the config that certifies.
This is the historical contracted-task baseline.
It is not the live repair target.

\textbf{Policy evaluation.}
Repeated balanced cross-validation: pick a consensus form on a train split of
size $s$, score end-to-end match on the complement.
On contracted tasks, $s{=}10$ ($N{=}20$), $B{=}2000$ splits, same seed.
On the HumanEval+ run in this draft, $N{=}10$ so $s{=}5$.
Leave-one-out and a single split-half are sensitivity only; we do not headline
the Gate~0 split-half medoid (74.3\%).

The shipped HumanEval \texttt{canonical\_solution} is an external baseline, not
the protocol canon.

\section{Experimental Setup}
\label{sec:setup}

\subsection{Contracted tasks}
\label{sec:setup-contracts}
Two scopes, never pooled into one headline.
\textbf{SBES:} 12 contracts, 3{,}600 generations.
\textbf{MSR:} 15 tasks (12 base + 3 \texttt{\_strict} variants), 4{,}500
generations.
Models: GPT-4o-mini, GPT-4o, Claude Sonnet 4.5.
Temperatures: $\{0.0, 0.3, 0.5, 0.7, 1.0\}$.
$N{=}20$ per config.

Gate~0 analysis uses 220 complete configs (MSR grid 225 minus the entire
\texttt{is\_prime\_strict}$\times$Claude cell, 5 configs).
The three \texttt{\_strict} variants were not validated against a real MISRA~C
or NASA Power-of-10 rule set; those names are inspiration only.

Historical artifacts \texttt{outputs/*.json} and \texttt{outputs/gate0/} are
first-valid repair.
Certified Consensus repair was replayed without new LLM calls into a parallel
tree (\texttt{outputs/consensus_repair/}, Gate~0 on that tree in
\texttt{outputs/gate0_consensus/}).
If nothing certifies (\texttt{binary\_search\_strict}, 15 configs), raw
generations are copied through; no form is invented.

\subsection{HumanEval+}
\label{sec:humaneval}
Prompts are the 164 HumanEval tasks.
The oracle is HumanEval+ extra tests~\cite{liu2023evalplus}, not the original
hidden file.
Dataset pin: \texttt{evalplus==0.3.1}, HumanEvalPlus \texttt{v0.1.10},
\texttt{dataset\_md5 = 916d9bfe7b490c2447245ec91595fa4f}.
This draft reports a 30-task slice (seed 20260826; ids stored in sorted order),
not all 164.
Grid: 30 tasks $\times$ 2 models (GPT-4o-mini, Claude Sonnet 4.5,
\texttt{claude-sonnet-4-5-20250929}) $\times$ $T\in\{0.0,0.7\}$ $\times$
$N{=}10$ $=$ 1{,}200 generations / 120 configs.
Completions are stitched onto the prompt and scored in network-disabled Docker
(\texttt{python:3.13-slim}, digest pinned in the experiment manifest).
Untrusted code is not executed on the host.
There is no style or MISRA-style contract on this run: certified means plus
tests pass.
A dummy contract sets only \texttt{function\_name} to the HumanEval entry
point so function substitution (Section~\ref{sec:skyt}) can target that
\texttt{def}.
The human \texttt{canonical\_solution} is scored as a baseline.

\subsection{Tool under test}
\label{sec:skyt}
\skyt{} is a post-generation canonicalizer, not a generating agent.
On contracted tasks, repair uses the labeled policy (first-valid or certified
consensus) and a property-based transformer, then re-runs the oracle and rolls
back if tests fail.

On HumanEval+, we replay Certified Consensus on the \emph{same} 1{,}200
programs (no second API draw).
Agent components are off.
The live ladder is:
if distance to the stored consensus form is ${<}0.1$, leave the code unchanged
(this is \emph{not} protocol identity, which is $10^{-12}$);
else try Level~2 (delete statements absent from the consensus form if plus
tests still pass);
else Level~3 (replace the named function's AST with the consensus function and
emit source with \texttt{astor}).
Level~3 records a zero distance without remeasuring; paper scores re-extract
properties from the saved programs.
Plus tests are re-run; failure rolls back to the original generation.

\section{Discussion}
\label{sec:discussion}

Measurement and policy answer different questions.
Table~\ref{tab:gate0-pre} and Table~\ref{tab:he-table1} describe scatter of
samples.
Table~\ref{tab:gate0-post} and Table~\ref{tab:he-table2} describe samples after
a chosen repair target.
Certified Consensus is a center among verified forms, not a quality-best
program and not the HumanEval human file.

On HumanEval+, most of the certified-pairwise increase is Level~3 substitution
of the stored consensus function.
An ideal post-\skyt{} certified pairwise of 100\% on configs that have a canon
would mean every plus-passer is that stored program.
Leftover disagreement in this run is the 20 configs with no canon, the 59
generations in $(0,0.1)$, and pretty-print noise from \texttt{astor}.

Plus-pass moving 80.5\%$\rightarrow$83.3\% is expected if a failing generation
receives a function body that already passed plus tests.
We do not lead with that delta.

First-valid on contracted tasks improves structure less than consensus and
introduces regressions.
Consensus repair on those tasks improves structure with rescues rather than
regressions in the Gate~0 replay.
Those two sentences are why C2 is in the paper.

\section{Threats to Validity}
\label{sec:threats}

\paragraph{Two pairwise columns.}
Email figures used certified pairwise (among passers).
The freeze's primary pairwise report is end-to-end (MEASURE~1).
This paper reports both.
Dropping configs with fewer than two plus-passers conditions certified
pairwise on tasks the model can already pass.

\paragraph{In-sample Table~2.}
HumanEval+ consensus is selected from the same $N$ that is rewritten and
rescored.
Held-out rewrite (pick on train, apply on test) is not in this draft.
CV scores held-out match \emph{without} rewrite.

\paragraph{Function substitution.}
Level~3 replaces the entry-point function with the stored consensus AST.
Of 171 HumanEval+ rewrites, 154 are that substitution.
Do not read Table~2 as evidence of a better generator.

\paragraph{Skip threshold versus identity.}
Protocol identity is distance $0$ ($10^{-12}$).
The transformer leaves $d<0.1$ unchanged.
Those cutoffs are different jobs.
Transformer \texttt{final\_distance} after Level~3 is not a paper score.

\paragraph{$N$ and CV batch.}
Contracted tasks use $N{=}20$ and CV $s{=}10$.
HumanEval+ in this draft uses $N{=}10$ and $s{=}5$.
That is the operational design of this run, not the freeze $s{=}10$.

\paragraph{Task count.}
Results~B is 30 of 164 HumanEval+ tasks.
A later full-set run does not change C1--C2 or the Table~2 in-sample caveat.

\paragraph{First-valid on HumanEval+.}
Option~C (both repair policies) is reported on contracted tasks.
HumanEval+ Table~2 is consensus only.

\paragraph{Oracle.}
Certified inherits the suite.
Some contracted cells have weak tests (\eg{} \texttt{slugify}/GPT-4o at
$T{=}0$).
Plus tests are finite; \skyt{} can copy a passing mode that is still wrong off
suite.
HumanEval/130 plus inputs with huge integers were capped; the worker uses a
per-case time limit.

\paragraph{Construct.}
Distance 0 on 14 extractors is not observational equivalence.
Several property names sound semantic (\texttt{logical\_equivalence},
\texttt{complexity\_class}, \texttt{termination\_properties}); they are AST
heuristics.
\texttt{complexity\_class} flags are candidates only.
We did not ablate properties against a clone-detection baseline.

\paragraph{Contamination and models.}
HumanEval prompts are likely in pretraining.
Match-to-human 9.3\% does not rule out other memorized solutions.
Two closed APIs; $T{=}0$ is not bit-deterministic; draws are a timestamped
snapshot.

\paragraph{Contracted-task grid.}
\texttt{binary\_search\_strict}: 0/20 compliant in analyzed cells.
\texttt{is\_prime\_strict}$\times$Claude never completed.
Author-written tasks; HumanEval+ is the external-task check.
The extractor does not transfer to multi-file SWE-bench~\cite{jimenez2024swebench}.

\paragraph{Tool identity.}
HumanEval+ replay used the traditional transformer with agents off, not the
full modular pipeline.

\section{Conclusion}
\label{sec:conclusion}

We argue for measuring structural dispersion of LLM code with an explicit
protocol, not with a single first-passing snapshot.
On contracted tasks the behavioral--structural gap survives after removing the
first-compliant confound; first-valid and certified consensus are different
repair policies.
On a 30-task HumanEval+ run, passing tests does not imply the same structure,
and match to the shipped human solution is rare.
\skyt{} on those programs is batch canonicalization toward the in-sample
consensus form, scored with the same ruler.

Remaining work: a held-out rewrite evaluation, first-valid on the same
HumanEval+ generations, aligning the transformer skip with distance 0 on a new
output tree, the 164-task grid under the locked adapter, and an artifact
package (dataset hash, Docker digest, seeds).
