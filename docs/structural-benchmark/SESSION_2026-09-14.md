## 1. Does the protocol need fixing?

Starting question was whether the repeatability protocol itself is broken.

Conclusion: **no.** The ruler is not the broken part. What is weak is how the
*tool* gets scored with that ruler.

The protocol already does the job it was locked to do: draw *N* times, decide
when two programs are the same form, report scatter with failures included, and
treat "which form do we repair toward" as a **policy** rather than a
measurement. Certified Consensus versus first-passer is exactly that policy
split. Cross-validation exists precisely because counting matches inside the
same *N* programs used to pick the winner is optimistic.

Redesigning the ruler so that post-repair numbers look better would be painting
the bullseye after the throws.

What to improve instead, in order of honesty-per-effort:

1. **Held-out rewrite.** Pick the form on one split, apply repair only to the
   complement, then score. No new API spend. Answers "does a frozen form stick
   to programs that had no vote in choosing it?"
2. **First-passer repair on the same stored HumanEval+ generations.** The
   missing half of the policy comparison. Replay only, new output tree.
3. **Full task coverage** if external weight is wanted. More tasks, not a
   smarter ruler.
4. **Transformer cleanup** (skip threshold versus identity threshold) only as a
   parallel sensitivity tree, and only with explicit approval, because it is a
   runtime change.

Not to be changed: the meaning of certification, end-to-end pairwise as the
primary pairwise report, "canon = most reproduced verified form" rather than
best program or human reference, and the rule that no form is invented when
nothing certifies.

## 2. The protocol, step by step

**Setup.** One *config* is one task x one model x one temperature. Draw *N*
independent generations from the same prompt (N=20 on the contracted tasks,
N=10 on the HumanEval+ run).

**Step 1 — certify each generation.** "Certified" differs by dataset. On
contracted tasks it means the behavioral oracle passes *and* the contract
checker passes. On HumanEval+ it means the EvalPlus extra tests pass; the
original HumanEval base tests are stored separately and never mixed into
certification. Programs the extractors cannot represent are structurally
invalid and are excluded from the structural math.

**Step 2 — fingerprint each generation.** Reduce each program to a vector of 14
AST-level properties (control-flow signature, data-dependency graph, execution
paths, complexity class, recursion schema, normalized AST structure, and so
on). Two programs are the *same form* when the distance between their vectors
is zero. The implementation uses `ZERO_TOL = 1e-12`, which means "this is
zero," not "close enough."

**Step 3 — bucket the certified programs.** Group certified programs into
distance-zero equivalence classes. Transitivity is checked explicitly first,
because "largest class" is meaningless if the relation can chain `A~B`, `B~C`
without `A~C`:

```108:120:src/repeatability_protocol.py

    matrix: Sequence[Sequence[Distance]],
    indices: Iterable[int],
    *,
    validate_transitivity: bool = True,
    validate_matrix: bool = True,
) -> List[List[int]]:
    """Return distance-zero equivalence classes in deterministic order.

    Modal mass only has a coherent meaning if distance zero is an equivalence
    relation. The explicit transitivity check prevents union-find from silently
    joining a non-transitive chain into a fictitious class.
    """
```

**Step 4 — pick the canon (Certified Consensus).**

1. Take the largest class: the form reproduced most often among programs that
   verified.
2. If several classes tie on that size, all their members become candidates.
3. Among candidates pick the medoid, meaning smallest mean distance to *all
   other certified* programs, not just to its own class.
4. Break remaining ties by source string, then index, so the pick is
   deterministic.

```206:209:src/repeatability_protocol.py
    index = min(
        candidates,
        key=lambda i: (mean_distance(i), tie_break_keys[i], i),
    )
```

The result is an **observed generation**, never a synthesized program. If zero
programs certify there is no canon: repair is skipped and the raw output is
copied through.

**Step 5 — repair the others toward that form.** For each remaining program,
measure distance to the stored canon and take the first rung that applies:

- distance exactly 0 → already the canon form, skip
- distance < 0.1 → left unchanged as "close enough." This threshold is **not**
  protocol identity, which is `1e-12`. On the HumanEval+ run 59 generations sat
  in that gap and were never rewritten.
- otherwise **Level 2**: delete statements the canon does not have, keeping the
  result only if tests still pass
- otherwise **Level 3**: replace the named function's AST with the canon's
  function and re-emit source

Level 3 performed 154 of 171 rewrites on the HumanEval+ run. It is function
substitution. It also records `final_distance = 0.0` without remeasuring, so
that field is never used as a score; the paper re-extracts properties from the
saved programs instead.

**Step 6 — validate the persisted artifact, or roll back.** After a rewrite the
oracle runs again on the exact code about to be written to disk. If tests break,
the transformation is reverted to the original generation. That rollback is what
exposed the 69 MSR / 14 SBES behavioral regressions under the first-passer
policy.

**Step 7 — score.** Re-extract fingerprints from the saved files and report:

- **End-to-end pairwise exact-match** (primary): over all `C(N,2)` pairs, how
  often do two draws both certify *and* match? Pairs containing a failure count
  as zero. Defined on every config.
- **Certified pairwise** (secondary): same check restricted to pairs of
  certified programs. Undefined when fewer than two certify, so those configs
  drop out of that column, which is why it can exceed the pass rate.
- **Certified modal mass**: largest certified class divided by *N*.
- **Held-out cross-validation**: pick a consensus form on a train split, score
  match on the complement. s=10 on contracted tasks, s=5 on the N=10 run.

Inference aggregates one score per task or contract and uses a cluster
bootstrap. Never a Wilson interval on `C(N,2)` pairs, which are not independent
trials.

**The structural catch.** Steps 4 through 7 run over the same *N* programs: the
winner is picked from those N, pasted into those N, and matches are counted on
those N. Cross-validation is the only part that looks at programs which had no
vote in choosing the canon.

## 3. What this gives a developer in practice

It makes a question measurable that CI cannot currently ask. Today the build
asks "did this generation pass?" The protocol adds "if I ask again, do I get the
same program?"

- **A regeneration check, like a flaky-test detector.** Point it at a prompt in
  your build, sample it *k* times, test, fingerprint the passers, report
  end-to-end pairwise. A low number is evidence that the step cannot be treated
  as reproducible. Teams assume temperature 0 plus a pinned model gives
  determinism; it does not.
- **A second axis for choosing model and temperature.** Observed on the
  HumanEval+ run: gpt-4o-mini at T=0.7 passed 78.7% of the time but only 50.3%
  of its passing pairs shared a form. Accuracy benchmarks call that setting
  fine. If you need the same artifact twice, it is not.
- **A diff-noise budget.** Two passing regenerations differ on roughly 13% of
  lines, about 2.7 lines on a 12-line function, rising to 23% at T=1.0. That is
  review effort spent for zero behavioral gain.
- **Freeze-and-verify instead of freeze-and-hope.** The instinct is to keep the
  first green output. The first passer is the most-reproduced form only about
  40% of the time, and repairing toward it broke working programs. Better: keep
  the form the model reproduces most, ship that, and use later generations to
  check for drift with a named reference and a distance attached.

What it does not do: make the model deterministic, prove semantic equivalence,
or survive a weak test suite (weak tests mean freezing a passing-but-wrong form
and then mass-producing it). Scope today is single Python functions.

The honest gap remains that the repair evidence is in-sample. It shows batch
cleanup under a test suite works. It does not yet show the *next* independent
sample will match a frozen form.

## 4. Are we building a HumanEval-style structural benchmark?

Partly, and the framing matters.

HumanEval bundles three things: prompts, a test oracle, and a metric. EvalPlus
did not invent new prompts; it kept the same 164 and strengthened the oracle.
The structural protocol is the same kind of move one layer over: keep the
prompts, keep the tests, add a structural report. It is a benchmark **overlay**,
so it rides on HumanEval+, MBPP, or in-house tasks. Writing fresh prompts would
be the wrong project.

**Already benchmark-grade.** Metrics defined and deterministically implemented
in `src/repeatability_protocol.py`. Reproducible harness: dataset md5 pinned
with loaders that refuse a mismatched hash, sandbox image pinned by digest,
network disabled, fixed seeds for sampling and bootstrap. Specified aggregation
and inference.

**Missing before anyone else adopts it.**

1. **The sameness oracle is not validated.** HumanEval's oracle is tests and
   nobody argues. Here the oracle for "same program" is 14 extractors, with no
   ablation and no comparison against clone detection or AST differencing. If
   the ruler is the contribution, the ruler is the least-tested part.
2. **Task coverage.** A benchmark cannot be a preregistered subset.
3. **N is not fixed.** `pass@k` names its k. Two different N values are in use,
   with the CV split size following along.
4. **No baseline table** others can extend.

Net: a measurement protocol with a working reference implementation, not yet a
benchmark others adopt. Those are two different deliverables.

## 5. What validating the sameness oracle actually requires

### 5.1 Distance zero already contains an AST hash

Overall distance is the **unweighted mean** of the 14 per-property distances, so
distance zero requires every property to agree:

```729:740:src/foundational_properties.py
        total_distance = 0.0
        property_count = 0
        
        for prop_name in self.properties:
            if prop_name in props1 and prop_name in props2:
                prop_distance = self._calculate_property_distance(
                    props1[prop_name], props2[prop_name], prop_name, contract
                )
                total_distance += prop_distance
                property_count += 1
        
        return total_distance / property_count if property_count > 0 else 1.0
```

One of those 14 is a straight MD5 equality test on the dumped AST:

```749:763:src/foundational_properties.py
        elif prop_name == "normalized_ast_structure":
            # Check contract variable naming policy
            use_alpha_renaming = self._should_use_alpha_renaming(contract)
            
            if use_alpha_renaming:
                # Use α-renamed hash for variable-name-agnostic comparison
                alpha_hash1 = prop1.get("alpha_renamed_hash", prop1.get("ast_hash"))
                alpha_hash2 = prop2.get("alpha_renamed_hash", prop2.get("ast_hash"))
            else:
                # Use actual AST hash (variable names matter)
                alpha_hash1 = prop1.get("ast_hash")
                alpha_hash2 = prop2.get("ast_hash")
            
            return 0.0 if alpha_hash1 == alpha_hash2 else 1.0
```

Consequence: **"same form" can never be more permissive than normalized-AST-hash
identity.** The other 13 properties can only make the relation stricter. That
reframes the reviewer question from "are these the right 14 properties?" to
"what do the other 13 contribute to the headline?" If distance zero fires
exactly when the AST hashes match, the 14 properties are a descriptive layer and
the operative equivalence relation is AST hashing. That is a defensible design,
but it has to be stated rather than buried under fourteen semantic-sounding
names.

### 5.2 Two failure directions, two different threatened claims

- **Too strict (false splits)** — two genuinely same-shaped programs called
  different. This *inflates* the measured gap, which is the headline empirical
  finding. This is the dangerous direction here.
- **Too coarse (false merges)** — two different programs called the same. This
  inflates post-repair match rates, threatening the tool-scoring claim.

Reflexive worry goes to the second. Actual exposure is mostly the first.

### 5.3 Concrete validation steps, cheapest first

**(a) Ablation.** Recompute the headline using only `normalized_ast_structure`
and compare against the full 14, then drop each property in turn and see whether
any number moves. Runs on existing artifacts, no API spend. Either outcome is
reportable and both beat the current silence.

**(b) Metamorphic tests for false splits.** Apply edits that should *not* change
the form and assert distance stays zero: reformatting, comment changes, local
renames under flexible naming, docstring rewording, reordering independent
statements (expected answer stated explicitly, since `statement_ordering` is one
of the 14).

Start with docstrings. The hash is taken over `ast.dump` of the *unmodified*
parsed tree, and docstrings live in the AST as `Expr(Constant(...))` nodes:

```448:456:src/foundational_properties.py
        # Create normalized AST hash (original, variable-name-sensitive)
        ast_dump = ast.dump(tree, annotate_fields=False)
        structure["ast_hash"] = hashlib.md5(ast_dump.encode()).hexdigest()
        
        # Create α-renamed AST hash (variable-name-agnostic)
        try:
            alpha_renamed_tree = self._alpha_rename_ast(tree)
            alpha_dump = ast.dump(alpha_renamed_tree, annotate_fields=False)
            structure["alpha_renamed_hash"] = hashlib.md5(alpha_dump.encode()).hexdigest()
```

So two logically identical functions whose docstrings are worded differently
register as different structures. On HumanEval+ this is likely muted, because
the docstring arrives from the stitched prompt. On the contracted tasks the
model writes its own and models reword docstrings constantly. Whether this
materially moves the 61-67% figures is **unmeasured**; the metamorphic suite
settles it.

**(c) Soundness probe for false merges.** The α-renamer's built-in allowlist is
seven names:

```496:501:src/foundational_properties.py
            def visit_Name(self, node):
                # Rename variable references
                if node.id not in ['range', 'len', 'print', 'max', 'min', 'sum', 'abs']:  # Built-ins
                    if node.id not in self.var_map:
                        self.var_map[node.id] = f"v{self.counter}"
                        self.counter += 1
                    node.id = self.var_map[node.id]
```

Everything else (`sorted`, `enumerate`, `any`, `str`) is renamed to `v{n}` as if
it were a local variable. Two programs differing only in which non-allowlisted
function they call can therefore collapse to the same α-renamed dump.
`control_flow_signature` records call names and may catch that; whether it
always does is testable. Sample distance-zero pairs, inspect, report precision.

**(d) Discriminant validity.** Run the same pairs through exact string equality,
plain normalized AST hash, and a tree-edit-distance tool. Show where the
relation disagrees with each and argue why that difference is wanted. This is
what answers "you reinvented AST hashing with extra dials."

**(e) Human agreement.** Sample pairs, have two or three people independently
label "same implementation or not," compute agreement, then report precision and
recall of distance zero against that consensus. This converts extractors into a
validated instrument and is what a benchmark contribution needs. Separate
project.

### 5.4 Freeze boundary

Measuring the extractors is analysis and needs no approval: ablations over
existing artifacts, plus new test files. But `src/foundational_properties.py` is
runtime code. If a metamorphic test reveals real brittleness, *fixing* it is a
runtime change requiring explicit approval, and it would invalidate every number
currently in the draft.

Sequence therefore matters: measure first, decide later, keep any fix in a
parallel tree.

## 6. Standing guardrails referenced during this session

- Frozen runtime: Certified Consensus pick, repair toward that stored form,
  post-oracle validation with rollback, no canon invented when nothing
  certifies. Runtime changes require explicit approval.
- Do not overwrite `outputs/gate0/` or `outputs/humaneval_plus/pilot/`.
- Never merge the three datasets into one headline.
- Do not score the tool by `pass@k` or by match to a human reference solution.
- `*_strict` contract variants were never validated against a real MISRA C or
  NASA Power-of-10 rule set; inspiration only, no compliance claimed.
